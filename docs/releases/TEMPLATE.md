## Правила оформления (обязательны)

1. **Версии — SemVer**: `MAJOR.MINOR.FIX`
   - MAJOR — ломающие изменения (BREAKING), MINOR — новый функционал, FIX — исправления.
   - Тег ставится на коммит в `main`: `git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z`.
2. **Порядок секций** — как в шаблоне, всегда одинаковый.
3. **Каждый пункт** начинается с глагола («добавил», «исправил», «обновил»), одна мысль — один пункт.
4. **Секции «Что нового» и «Известные проблемы»** обязательны всегда.
5. **Секции сгруппированы** (Добавлено/Изменено/Исправлено/Удалено), а не смешаны в одну кучу.
6. **Дата** в заголовке — дата релиза (день пуша тега).
7. **Название релиза** — короткая суть («Первый релиз», «Проверка сочинений v2»), не повторяет номер версии.
8. Описания не редактируются задним числом — для изменений выпускается новый релиз.
