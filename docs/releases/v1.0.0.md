# v1.0.0 — «Первый релиз: базовая линия» (2026-11-18)

## 📌 Кратко

Первый публичный релиз проекта «Репетитор ЕГЭ»: полный код приложения перенесён с рабочего деплоя на Render в git-репозиторий и организован в структуру «Telegram Mini App» + «APK mobile app». Этот релиз — базовая линия для всех последующих версий.

## ✨ Что нового

### Добавлено
- Исходный код Telegram-бота и Mini App «Кабинет» (Python 3.12, aiogram 3.31, aiohttp 3.14)
- Android-приложение «Кабинет репетитора» (`APK mobile app/kabinet-repetitora.apk`)
- Учебные материалы ЕГЭ/ОГЭ (сочинения 2027), база знаний, ассеты и шрифты
- Dockerfile и скрипт деплоя
- README с описанием структуры, стека, запуска и переменных окружения
- Конвенция релизов: шаблон описания (`docs/releases/TEMPLATE.md`) и автоматическое создание релизов при пуше тега (`.github/workflows/release.yml`)

### Изменено
- Маршрут `/apk` в `bot.py` указывает на `../APK mobile app/kabinet-repetitora.apk` (APK вынесен в отдельную папку при организации репозитория)

## ⚙️ Технические детали

- Стек: Python 3.12, aiogram 3.31, aiohttp 3.14, reportlab/xhtml2pdf/pypdf/pypdfium2, playwright, PyJWT + cryptography (PS256, Яндекс Облако)
- HTTP API: `/api/data`, `/api/week.pdf`, `/api/materials/{id}`, `/api/pdf_link`, `/api/week/send`, `/apk`
- Аутентификация: `X-Init` (initData Telegram Mini App) и `X-Session` (JWT standalone-приложения)
- Код — слепок работающего образа с Render; исключённые при сборке файлы (`tests/`, `*.md`, `docker-compose.yml`) в релиз не входят
- **Не является BREAKING** — это первая версия, совместимость отсчитывается от неё

## 🚀 Как обновить

Обновление с предыдущих версий не требуется — это первый релиз. Развёртывание: см. README (локально, Docker, Render).

## ⚠️ Известные проблемы

- Тесты (`tests/`) и часть документации исходного проекта не перенесены — они отсутствовали в Docker-образе; будут добавлены отдельным релизом
- История git исходного проекта не входит (код перенесён слепком)

# 📋 Как оформлять описания последующих релизов

Эта секция — часть контракта проекта. Каждый следующий релиз оформляется по правилам ниже.

1. **Версии — SemVer** `MAJOR.MINOR.FIX`: MAJOR — ломающие изменения (префикс **BREAKING:** в описании), MINOR — новый функционал, FIX — исправления.
2. **Файл описания** — `docs/releases/X.Y.Z.md`, где `X.Y.Z` = номер тега. Создаётся **до** пуша тега.
3. **Структура описания** — строго по шаблону `docs/releases/TEMPLATE.md`, секции в том же порядке:
   - 📌 Кратко → ✨ Что нового (Добавлено / Изменено / Исправлено / Удалено) → ⚙️ Технические детали → 🚀 Как обновить → ⚠️ Известные проблемы → 📎 Ссылки
4. **Правила пунктов**: одна мысль — один пункт; пункт начинается с глагола; каждое изменение из «Что нового» упоминается один раз.
5. **Обязательные секции**: «Что нового» и «Известные проблемы» (если проблем нет — писать «Не выявлены»).
6. **Дата и название** в заголовке: дата релиза + короткое живое название, не дублирующее номер.
7. **Выпуск**: `git tag -a vX.Y.Z -m "vX.Y.Z: <название>" && git push origin vX.Y.Z` — GitHub Actions создаст релиз автоматически, описание будет взято из `docs/releases/vX.Y.Z.md`.
8. Описания релизов **не редактируются задним числом** — любое уточнение оформляется новым релизом.
